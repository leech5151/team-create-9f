# 볼링 레인 랜덤 배정

`Bowling Lane Draw.dc.html` (Claude Design 핸드오프)을 React로 구현한 앱.

```bash
npm install
npm run dev        # http://127.0.0.1:5273
npm run build      # dist/
npm run typecheck
```

## 구조

```
src/
  lib/assign.ts        배정 알고리즘 (셔플 → 300회 시뮬레이션 → 최소 점수 선택)
  lib/storage.ts       localStorage 직렬화 + 로드 시 스키마 검증
  lib/format.ts        날짜·공유 텍스트
  hooks/useRoll.ts     룰렛 상태 기계 (70ms 틱 / 1.2s 스핀 / 1.1s 착지)
  screens/             roster · draw · result · history
  components/          RollOverlay · ShareSheet · MemberSheet · BottomBar
  index.css            디자인 토큰과 모든 px/색상 값
```

## 배정 알고리즘

레인 수 = 가장 인원이 많은 티어의 인원수. 티어별로 셔플한 컬럼을 만들어
가로로 읽어 레인을 구성하고, 300회 중 점수가 가장 낮은 조합을 채택한다.

| 옵션 | 페널티 |
| --- | --- |
| 에버리지 균형 | 레인 평균의 표준편차 × 3 |
| 중복 방지 | 이전 회차에 같은 레인이었던 쌍마다 +12 |
| 성별 분배 | \|레인의 여성 수 − 전체 평균\| × 2 |

세 옵션을 모두 끄면 최적화할 대상이 없으므로 1회만 셔플한다.

측정값 (시드 명단 24명 / 8레인): 최적화 ON 편차 ±1.41 · 중복 0쌍,
OFF 편차 ±2.34 · 중복 3쌍.

## 프로토타입과 다른 점

- **멤버 CRUD + localStorage**: 프로토타입은 30명 하드코딩. 명단 화면
  `편집`으로 추가/수정/삭제, 명단·기록·진행 중인 추첨이 모두 저장된다.
  멤버는 이름이 아니라 `id`로 식별하므로 개명해도 기록이 유지된다.
- **결과 화면 토글**: 1a 카드 / 1b LANE BOARD를 세그먼트로 전환. 보드
  전환 시 하단 CTA·탭바까지 다크로 반전된다.
- **공유**: 프로토타입의 `카카오톡 공유` / `이미지 저장`은 동작하지 않는
  목업. Web Share API(미지원 시 클립보드 폴백)와 텍스트 복사로 대체했다.
- **티어 불균형 안내 문구**: 프로토타입은 "남는 인원은 마지막 레인에 4인으로
  묶입니다"라고 했지만 알고리즘은 그렇게 동작하지 않는다 (레인 수를 최대
  티어에 맞추므로 남는 인원이 아니라 **빈 자리**가 생긴다). 실제 동작에
  맞춰 문구를 고쳤다.
- **iOS 목업 프레임 제외**: 402px 기준 모바일 웹앱. 상·하단 여백은
  `env(safe-area-inset-*)`로 노치/홈 인디케이터를 실제로 피한다.
